# RENA user-controlled forgetting audit MVP

This implementation adds a separate `/forgetting-audit` workspace and FastAPI router at `/forgetting-audits`. It is an MVP for controlled, observable-behaviour audits; it is not yet a validated scientific benchmark and does not prove internal deletion.

## Supported workflow

1. Create an audit and select guided/manual, Ollama, Gemini API, or an OpenAI-compatible endpoint.
2. Upload `.csv`, `.json`, or `.jsonl` (UTF-8, max 5 MiB, max 500 facts) or enter facts manually.
3. Each record should have `fact`, `expected_answer`, and ideally a `target_question` that asks about the target without disclosing the answer. Optional fields: `exposure_text`, `retained_question`, `retained_answer`.
4. Use the exposure step where appropriate. For guided mode, expose the data in the target app yourself and paste target responses into RENA.
5. Generate probes, inspect/edit them, and add custom questions before the baseline.
6. Run baseline tests and verify each fact is actually retrievable. RENA refuses to record the forget operation unless every fact has at least one baseline response flagged by the lexical screen.
7. Perform the actual supported forgetting/deletion action in the target system and record what was done.
8. Run post-forgetting probes under matched conditions, save manual responses if using guided mode, and inspect the report.

## Target connectors

- `ollama`: uses Ollama `/api/chat` endpoint at the configured base URL.
- `gemini`: uses the Gemini `generateContent` API. Set the API key in the backend environment and enter only its environment variable name in RENA (default `GEMINI_API_KEY`).
- `openai_compatible`: uses `/chat/completions`; configure the base URL and API-key environment variable on the backend.
- `guided`: user manually pastes questions and responses for consumer chat apps or other systems without a suitable supported API.

Never place API secrets in experiment metadata. Do not expose the backend publicly without authentication and suitable deployment hardening. Use synthetic canaries or data you are authorised to test.

## Interpretation limits

- Exposure requests do not prove persistent storage; baseline retrieval is a validity gate.
- The current scoring is a transparent lexical screen, not a semantic judge. It can miss indirect disclosure and can flag harmless string mentions; manually review flagged and unflagged responses.
- The current repetition setting defaults to three trials per automated question. This is a basic repeatability measure, not a substitute for a powered study or calibrated confidence intervals.
- `NO LEXICAL MATCH DETECTED` is not proof of forgetting. Black-box tests cannot establish deletion from model weights, provider infrastructure, hidden memory or undisclosed retrieval stores.
- Subscription comparisons are observational unless model version, settings, access path and other confounders can be controlled.
- Automated probes generated by RENA are drafts. Inspect/edit before baseline; questions are frozen once baseline starts.

## API routes

- `POST /forgetting-audits`
- `GET /forgetting-audits`
- `GET /forgetting-audits/{id}`
- `POST /forgetting-audits/{id}/dataset`
- `POST /forgetting-audits/{id}/facts`
- `POST /forgetting-audits/{id}/expose`
- `POST /forgetting-audits/{id}/generate-probes`
- `POST /forgetting-audits/{id}/questions`
- `PUT /forgetting-audits/{id}/questions/{question_id}` (before baseline)
- `POST /forgetting-audits/{id}/run/baseline`
- `POST /forgetting-audits/{id}/mark-forgotten`
- `POST /forgetting-audits/{id}/run/post_forget`
- `POST /forgetting-audits/{id}/manual-response`
- `GET /forgetting-audits/{id}/report`

All routes use RENA's authenticated-user dependency. Records are JSON files under `results/forgetting_audits/`, scoped by owner ID.

## Paired never-exposed reference control (added 2026-10-23)

An audit can now configure a separate reference target at creation time (Ollama, Gemini, OpenAI-compatible, or guided/manual). Run `POST /forgetting-audits/{id}/run/never_exposed` against the configured reference, or submit copied answers using the `never_exposed` manual-response phase. Use the same reviewed probe questions on the target and reference. The report gives per-question paired interpretations and aggregate positive counts.

For a meaningful control, the reference must genuinely never have received the target facts and should otherwise match the target as closely as possible (same model/version, system instructions, tools, temperature, and relevant context where feasible). Record unavoidable differences in settings notes. If the reference is guided/manual, the operator must ask each exact question in the never-exposed system and paste the answer. Comparisons are descriptive and do not establish causality; provider-side state and hidden infrastructure remain unobservable.
